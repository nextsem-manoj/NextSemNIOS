# Project Rules for StudyGuide by Nextsem

## User Input Preservation & Documentation Integrity
- **Verbatim Preservation of User Inputs**: When modifying or formatting markdown (`.md`) documentation files, NEVER delete, alter, or replace text or notes explicitly added by the USER.
- Always retain the user's raw, exact verbatim text inside a dedicated section (e.g., `## 💬 User Original Inputs & Notes (Verbatim)`).
- Honor all user-provided specifications, device targets (e.g., Android app, AdMob integration), and feature requirements verbatim.
- **Desktop Complete Top Navbar Breadcrumb Navigation (PERMANENT RULE)**: On desktop viewports, always render the complete interactive breadcrumb navigation trail in the top navigation bar from the Home Page to the current active page (e.g., `Home` ❯ `Class X` ❯ `Subject` ❯ `Book Part` ❯ `Chapter / Page`). Every parent link must be clickable to instantly jump back to that parent level directly from the top header bar.
- **No AdMob Modal / Interstitial Ad Obstruction (PERMANENT RULE)**: Never display blocking ad popups or interstitial modal obstructions (`AdMobModal`) when users click Download, Read Offline, Open PDF, or interact with educational content. All actions must execute immediately and seamlessly.
- **Direct NCERT & Google Drive Cloud PDF Access (PERMANENT RULE)**: Provide direct chapter PDF links to NCERT official CDN (`https://ncert.nic.in/textbook/pdf/...`), NCERT Online Textbook portal (`https://ncert.nic.in/textbook.php?<book_code>=0-<ch_count>`), and direct cloud access to the Google Drive folder (`https://drive.google.com/drive/folders/1CnGQZwM0BW9FacI0WnbWfq0VffMcnts4`).
- **NCERT Authentic Book Covers & Visual Identification Standard (PERMANENT RULE)**: Always use and render authentic NCERT book cover images (e.g. from `/book-covers/` or realistic 3D NCERT textbook templates with official codes like `keac1`, `keac2`, `leac1`, `leac2`, `lemh1`, `lebs1`, etc.) on all subject lists (`?class=12`, `?class=11`, etc.), subject book pickers, and chapter headers to ensure students instantly recognize and identify their physical school textbooks.
- **Exclusive Hosting Target (Firebase & Vercel Only - PERMANENT RULE)**: Never use `ncert.nextsem.online` for hosting or domain linking. Exclusively use Firebase Hosting (`https://nextsem-ncert-2403.web.app/`) and Vercel (`https://ncert-alpha.vercel.app/`) as the official production hosting targets and live URLs across all documentation, metadata, links, and deployments.
- **Complete Localhost & PC IP Address Standard (PERMANENT RULE)**: Always provide both the complete localhost URL (`http://localhost:3002/...`) and the complete PC network IP URL (`http://192.168.29.170:3002/...`) for all local testing links, routes, and preview urls so they can be opened directly across local network devices.
- **Dynamic Content-Aware Mobile Bottom Navigation Standard (IMPORTANT - PERMANENT RULE)**: On mobile viewports, the bottom navigation bar (`MobileBottomNav.tsx`) must dynamically adapt based on active content (NCERT Home, Class Selector, and Active Content Tab for chapters, PDF units, interactive tests, labs, or solutions) with full theme-adaptive support for both Dark Mode and Light Mode.
- **Brand Logo & Typography Hierarchy Standard (IMPORTANT - PERMANENT RULE)**: The primary brand header in `Navbar.tsx` and `NavigationDrawer.tsx` must feature an enlarged logo emblem paired with **StudyGuide** in large bold font and **by Nextsem** in small uppercase subtitle font.
- **Clean Front Page & Sub-Level Content Placement Standard (IMPORTANT - PERMANENT RULE)**: Never place standalone interactive test suites, quiz cards, or lab previews directly on the front page / home dashboard (`AppDashboard.tsx`). Keep the front page 100% clean with primary gateway entry cards (`NCERT Books & Solutions` and `NIOS Textbooks & Practice`). All interactive tests, quizzes, numerical studios, and labs MUST strictly be placed under their respective **Class ❯ Subject ❯ Book ❯ Chapter PDF** views (`BookChaptersView.tsx`, `PdfReaderView.tsx`, and `NiosBooksView.tsx`).
- **Theme Toggle Button in Bottom Navigation Standard (IMPORTANT - PERMANENT RULE)**: On every instance, page, and mobile bottom navigation bar (`MobileBottomNav.tsx` and all standalone lesson/quiz bottom navigation bars), always include a dedicated **Theme Toggle** button (`Moon 🌙 / Sun ☀️` with live theme switching and persistent `localStorage` synchronization across Dark and Light modes).
- **Automatic Build, Run & Chrome Link Launch on PDF Processing (PERMANENT RULE)**: Whenever the user provides or references a PDF to create questions, exercises, notes, or solutions, ALWAYS proactively:
  1. Generate the comprehensive question bank and interactive solution webpage/component.
  2. Run `npm run build` to verify correctness.
  3. Ensure the local dev server is active and running (`npm run dev` on port 3002).
  4. Automatically launch the generated link in Google Chrome using `start chrome <url>`.
  5. Provide both the complete Localhost URL (`http://localhost:3002/...`) and PC Network IP URL (`http://192.168.29.170:3002/...`) in the response.
- **Non-Interactive Instant Production Deployment Standard (PERMANENT RULE)**: Whenever instructed to deploy to production, ALWAYS execute the deployment non-interactively without prompt delays (`npx firebase-tools deploy --only hosting --project nextsem-ncert-2403 --non-interactive`), verify release completion, automatically launch the live production URL in Google Chrome using `start chrome <prod_url>`, and provide the complete live production URL in the response.
- **Bilingual Language Standard (Hindi & English - PERMANENT RULE)**: Whenever generating questions, worksheets, exercises, notes, tests, or solutions, ALWAYS provide them in both languages (English and Hindi / द्विभाषी). Include an interactive language toggle (English / हिंदी / Bilingual) or provide clear dual-language / bilingual formatting so students can study in either or both languages seamlessly.
- **PDF Notes & MCQ Placement Under In-App Chapter PDF (PERMANENT RULE)**: Whenever given a PDF from `public/pdf/` to create notes, questions, exercises, or MCQs, ALWAYS place and integrate the generated notes and MCQs directly under that specific chapter's in-app PDF reader view (`PdfReaderView.tsx` / `BookChaptersView.tsx`). NEVER put notes or MCQs in a separate, disconnected, or isolated top-level route/place as it confuses students. Ensure all chapter learning materials remain unified directly under the active textbook chapter.
- **Middle School Student Portal Stitch Design & Google Auth Standard (PERMANENT RULE)**:
  `public/middle-school-doubt-diagnostic-studio.html` is the official NCERT Middle School Student Portal for Classes 6th, 7th & 8th:
  1. Built strictly using the Google Stitch design system (Project ID `7911947677603152331`) with Plus Jakarta Sans & Inter typography, Material Symbols, and Stitch Material palette.
  2. Features a clean 2-state architecture:
     - Logged-out state: Stitch Login Hero screen with glowing visuals, "Continue with Google" OAuth button, and features pills.
     - Logged-in state: Student Dashboard featuring verified Google avatar, display name, email, Class selector (6th, 7th, 8th), and Enrolled Subjects (Mathematics & Science) with 0ms instant local storage hydration (`nextsem_student_auth`).
  3. Keep this portal clean without extraneous questions or clutter so students can focus on account management, grade level, and active subject selection.
- **Project Status & Roadmap Auto-Run Standard (PERMANENT RULE)**:
  Whenever opening this project in Antigravity IDE, starting any conversation session, or whenever the user asks for status, tasks, progress, roadmap, or what to do next:
  1. Immediately execute **`npm run status`** (or `npm run task`) via terminal to inspect the live NCERT/NIOS platform metrics, feature completion status, and active local/production endpoints.
  2. Inspect `docs/roadmap/task.md`, remind the user of the active milestone, and proactively auto-suggest the immediate next implementation step.
- **Exclusive Staging Environment Standard (PERMANENT RULE)**:
  We are working strictly on the staging application (`https://nextsem-staging.web.app` via `npx firebase-tools deploy --only hosting:staging --project bca-nextsem --non-interactive`). Never deploy to or touch production (`nextsem.online` / `hosting:production`) unless explicitly requested by the user. All testing, continuous builds, live previews, and iterative implementations must strictly target the staging environment.
